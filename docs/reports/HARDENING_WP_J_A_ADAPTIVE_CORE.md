## 3. The pinned numbers — what the formula ACTUALLY produced

The design contract's arithmetic was correct to the unit. **No number in §3.3 needed
correcting.** Every value below is what `buildAdjustmentProfile` returned on the first run.

`FOLD_TO_CBET_FLOP`, prior **4500**, K **40**:

| input | confBps | observedBps | estimateBps | deviationBps |
| --- | --- | --- | --- | --- |
| `LEARNED_MODEL` 10000 over n=2 | **476** | 10000 | **4762** | **+262** |
| `LEARNED_MODEL` 7500 over n=100 | **7143** | 7500 | **6643** | **+2143** |

`|+2143| > |+262|` — asserted, not eyeballed. Note the direction of the point: the *smaller*
raw reading (75% vs 100%) moves the strategy *further*, because the sample is real.

Pooling both sources on the same stat — `MANUAL_HUD` 6000/n=40 + `LEARNED_MODEL` 8000/n=60:

| quantity | value |
| --- | --- |
| pooled `sampleN` | 100 |
| pooled `observedBps` (sample-weighted mean) | **7200** |
| `confidenceBps` | 7143 |
| `estimateBps` | **6429** |
| `deviationBps` | **+1929** |
| `sources` | both rows survive: `{MANUAL_HUD, 6000, 40, 'HUD'}` and `{LEARNED_MODEL, 8000, 60, '자체 관측'}` |

Saturation: `sampleN = Number.MAX_SAFE_INTEGER` sanitizes to `ADAPTIVE_MAX_SAMPLE_N`
(1e8), yields `confidenceBps === 10000` exactly (never above), and the estimate becomes the
reading verbatim. Every field stays a safe integer.

Duplicate `(key, source)`: three `WTSD` rows (two manual, one learned) collapse to two source
refs; the surviving manual ref is the LAST one (3400 / n=80) and its note becomes
`최신 값 · duplicate reading for this stat and source; last used (superseded 1)`. Pooled over
n=130 → `observedBps` 3208.

## 5. Deviations from the design contract

1. **`@gto-self/shared` is NOT declared as a dependency.** The brief listed it, but also said
   "declare nothing you don't import", and J-A imports nothing from it (`clampBps` /
   `BPS_TOTAL` come from `strategy-core`, the confidence curve from `player-core`; there is
   no money and no `Result` in the profile layer). **J-C will need it** for `MilliBB` in the
   sizing DTO and should add `"@gto-self/shared": "workspace:*"` at that point. The design
   contract's §1 permission is unchanged; only the manifest is honest about today.

2. **Two extra ESLint blocks got the upward ban** beyond the five enumerated: the
   `packages/strategy-core/src/adapter/**` seam block and the
   `packages/coinpoker-parser/**` block (plus the `solver-lab` enumerated group). The adapter
   block is not optional — flat config is last-match-wins, so leaving it out would have made
   every file under `strategy-core/src/adapter/` a hole in the ban the block above it
   declares. The parser and solver-lab additions are one line each into groups that already
   enumerate every other package, and serve the same stated intent ("nothing below can import
   upward").

3. **`roundDivNonNegative` instead of a literal `Math.round(a / b)`.** Same result, no float:
   `floor((2a + b) / 2b)` is round-half-up for non-negative integers. This is `player-core`'s
   own technique in `confidenceWeightBps`, and it is what makes a profile byte-comparable
   across machines — which the determinism test relies on. Both call sites are non-negative
   by construction. Rounding still happens at exactly the two points §3.3 names.

4. **`ADAPTIVE_MAX_SAMPLE_N = 1e8` added.** Not in the contract. It is a numeric-safety bound,
   not a product heuristic: without it a corrupt `sampleN` near `MAX_SAFE_INTEGER` would push
   `2 * 10000 * n` past exact integer arithmetic and produce a silently wrong number in a
   function that is required to be total. Documented as such, and distinct from
   `MANUAL_HUD_MAX_EFFECTIVE_N`, which stays the caller's product cap.

5. **Two small additions to the API:** `emptyOpponentInput` (the identity input, used by the
   tests and useful to J-D/J-E for a seat with no data) and `ADAPTIVE_MODEL_KEY_COUNT`.
   Neither changes any behaviour.

## 6. Remaining risk

- **The anchors are review-bait by design.** `ADAPTIVE_PRIORS` decides where "no adjustment"
  sits for every rule J-C writes. They are all `HEURISTIC` with mandatory notes and are
  asserted never to say "GTO" or "solver", but a reviewer who disagrees with a value is
  disagreeing with a two-line data edit — that is the intent, and it is the right place to
  push back before J-C builds on them.
- **`MANUAL_HUD_MAX_EFFECTIVE_N` is enforced nowhere yet.** This package deliberately does
  not apply it. If `apps/web/src/server/adaptive-service.ts` (J-D) forgets the
  `min(handSample, 1000)`, a HUD hand count reaches the confidence curve raw and a
  street-scoped HUD stat gets a weight it did not earn. J-D needs a test for that clamp; a
  `profile.test.ts` assertion pins the division of labour but cannot enforce the caller's half.
- **The upward ban is not on `packages/db/**`.** J-B owns that block; if the adaptive-trace
  repository ends up importing `adaptive-core` types, that is a decision for J-B to state,
  not a hole I should have closed from here.
- **Nothing in this package produces a strategy yet.** `deviationBps` is computed and carried,
  but no rule reads it until J-C. The ADAPTIVE surface is therefore not yet reachable from
  the UI, and the J10 invariants about frequencies, sizing and multiway are still unwritten.

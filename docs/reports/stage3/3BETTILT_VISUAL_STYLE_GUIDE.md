# 3BetTilt 비주얼 스타일 가이드 (WP-S3-04)

Stage 3 에디토리얼 리디자인에서 **이미지·일러스트·OG 카드가 지켜야 할 규칙**. 자산 하나하나의
사양은 `3BETTILT_VISUAL_ASSET_MANIFEST.md`(같은 디렉터리)에 있고, 이 문서는 그 자산들이 공유하는
언어다. 팔레트 값은 `apps/fishtilt/src/app/globals.css` `@theme`(:116-247)과 라이트 블록(:268-339)에서
그대로 가져왔다 — 여기의 hex는 인용이지 새 토큰이 아니다.

**이 세션의 사실**: image-generation capability 없음. 이 문서와 매니페스트는 사람 또는 이후
image-capable 에이전트가 실행하는 사양이며, **어떤 이미지도 생성·커밋되지 않았다**. 자산이 없는
상태에서 레이아웃은 §7의 fallback 규칙으로 깨지지 않아야 한다(계약 AB).

**Stage 2 문서와의 관계**: `docs/reports/FISHTILT_WP6_VISUAL_ASSET_PLAN.md` §9의 "AI 이미지 도입
반대"는 소유자 결정(계약 W)으로 **override**됐다. 그 문서의 §3 데이터 도해 백로그, §4 OG 권고안 A(kind×topic
32장), §5 "텍스트는 DOM" 템플릿, §6 alt 판정법, §8 성능 논거는 **유지**된다. §7의 디렉터리
`public/img/<kind>/`는 이 WP의 `public/images/<role>/`로 **대체**된다. §9-4 금지 소재표는 §5에서 재정의한다.

## 1. 성격과 팔레트

성격(계약 R): **premium · modern · editorial · intelligent · friendly · slightly dramatic**.
한 문장으로 — *"잡지의 포커 특집 화보"*이지 *"카지노 배너"*가 아니다.

| 역할 | 다크 값 | 라이트 값 | 이미지에서의 쓰임 |
|---|---|---|---|
| ground-900 | `#090a0d` | `#f2f4f7` | 페이지 바탕. 이미지의 가장 어두운 그림자는 **이보다 어둡지 않게**(순흑 `#000` 금지) |
| ground-800 / panel-700 | `#101319` / `#171b21` | `#ecf0f5` / `#ffffff` | 이미지 안 "차콜"의 기준 명도. 펠트·벽·의자의 중간톤이 이 대역 |

| act-raise / act-call | `#e4572e` / `#2ba3a3` | `#c0410f` / `#17706f` | 데이터 도해 전용. **AI 이미지에는 넣지 않는다** |

**그레이딩 규칙**
- 톤: 차콜 기반 저채도. 그림자는 `#0b0d10`~`#101319` 사이로 들어 올리고, 하이라이트는 따뜻한
  텅스텐(약 3200K 느낌). 전체를 붉게 물들이지 않는다 — 피부톤은 자연색.
- **레드 예산**: 프레임 면적의 10~15%를 넘지 않는다(측정값이 아니라 **예산**이다). 레드는 하나의
  광원 또는 하나의 오브젝트에서만 온다. 레드 두 군데 이상이면 "네온"으로 읽힌다.
- 금색·황동·초록 펠트·파란 네온은 팔레트 밖이다. 펠트는 **차콜/그라파이트**, 필요하면 딥 옥스블러드
  (`brand-950 #3a1118` 대역)까지만.
- 대비: 이미지 위에 DOM 텍스트를 올리는 슬롯은 없다(§4). 따라서 이미지 자체에 텍스트 대비 요구는
  없고, 오직 **프레임 경계가 두 테마에서 보이는가**만 검사한다(§6).

## 2. 조명과 분위기 어휘

프롬프트에서 쓰는 공통 어휘. 매니페스트의 각 프롬프트는 이 어휘를 조합한다.

- **key light**: 테이블 위 한 점의 따뜻한 펜던트/스팟. 위에서 45°, 얼굴과 손을 잡는다.
- **rim light**: 브랜드 레드 계열의 가는 림. 어깨선·카드 모서리·칩 가장자리. 광원은 화면 밖.
- **fill**: 거의 없음. 배경은 `ground-800` 대역으로 잦아들되 순흑으로 뭉개지 않는다.
- **분위기어**: `quiet tension`, `moment before the decision`, `after-hours private room`,
  `editorial magazine cover`, `restrained`, `cinematic but not glossy`.
- **금지어**: `neon`, `casino floor`, `slot machines`, `Las Vegas`, `jackpot`, `luxury`, `gold`,
  `champagne`, `HDR`, `lens flare`, `glossy 3D render`.
- 렌즈: 50~85mm 느낌, 얕은 심도. 광각 왜곡·어안 금지. 필름 그레인은 미세하게만.

## 3. 피사체 규칙

- **사람**: 다양한 성별·연령(20대~50대)·인종. 한국어 사이트이므로 동아시아인 비중이 자연스럽되
  단일 인종으로 고정하지 않는다. **미성년자로 보이는 인물 금지.** 실존 인물·유명 프로 선수 닮음
  금지(프롬프트에 이름 사용 금지). 선글라스·후드·시가·정장 턱시도 등 "포커 클리셰" 지양.
- **테이블·소품**: 칩은 소수·아웃포커스·무액면. 실제 카지노 로고·칩 디자인·브랜드 카드 뒷면 금지.
  현금·지폐·동전·시계·보석 금지(계약 R "cheap casino / gambling banner" 배제, 돈 미화 금지).
  술·담배 금지.
- **카드**: AI 이미지 안의 카드는 **뒷면, 빈 앞면, 또는 프레임 밖**만 허용. 랭크·수트·핍이 조금이라도
  읽히면 그 생성물은 **불합격**(재생성 또는 크롭). 이유는 §5.
- **동물·마스코트·캐릭터·만화체** 금지. 이 브랜드는 사진적 에디토리얼이다.
- **About 페이지**: 사람 없음. "팀"을 암시하는 인물 사진은 계약 BH(가짜 team/person 금지) 위반이다.
  정물(책상·뒷면 카드·모눈종이·연필)만.

## 4. 텍스트는 절대 래스터에 넣지 않는다

- 제목·덱·라벨·숫자·워드마크(OG 제외)는 **live DOM**이다(계약 AA). 이미지에 글자가 생기면 불합격.
  모델은 한글을 쓰지 못하고, 영문이라도 로케일이 늘면 재생성 비용이 된다.
- 유일한 예외: OG PNG의 `3BETTILT` 워드마크. 브랜드명은 번역 대상이 아니다(WP6 §4-1 유지).
- 따라서 **이미지 위에 텍스트를 올리는 슬롯은 만들지 않는다.** 히어로는 항상 *Visual + HTML Title +
  HTML Description* 구조(계약 AA)이고, 이미지는 자기 프레임 안에서 끝난다. 이미지 위 스크림·오버레이
  텍스트가 필요해 보이면 레이아웃이 틀린 것이다.

## 5. 정확한 사실은 SVG/HTML/도메인 데이터로만 (계약 Y·Z)

AI 이미지는 **틀릴 수 있다**. 틀리면 안 되는 것은 코드가 그린다.

| 반드시 코드로 그리는 것 | 그리는 곳(기존/계획 컴포넌트) |
|---|---|
| 홀 카드·보드·로열 플러시 등 **모든 카드 앞면** | `PokerCards` / `PokerCard`, 계획 `BoardCards`, 홈 히어로 오버레이(WP-S3-05) |
| 족보 순서·빈도 | `learn-core categoryFrequency` → 계획 `CategoryFrequencyFigure`(WP6 §3 #6) |
| 13×13 매트릭스·레인지 | `RangeMatrix`, `RangeMatrixMini`, `HomeRangePreview`, 계획 `RangeEmbed` |
| 포지션 배치 | `PositionLegend`, 계획 `PositionDiagram` |
| 팟오즈·아웃츠·승률 | `PotOddsFigure`, `OutsFigure`, `EquityCalculator`, `Fact` |
| 베팅 순서·액션 타임라인 | 계획 `BettingTimeline`, `HandTimeline` |

**하이브리드 규칙**: AI가 *장면*(사람·테이블·조명·환경)을 맡고, 정확해야 하는 오브젝트는 그 위에
**결정적 SVG 오버레이**로 합성한다. 오버레이는 컴포넌트 코드이며 이미지 파일에 굽지 않는다. 오버레이의
위치는 프레임 대비 **퍼센트 안전 영역**으로 매니페스트에 고정한다(홈 히어로 = VA-01). 생성물은 그
영역을 *비워 두는* 것이 합격 조건이고, AI가 그린 카드를 오버레이가 "덮는" 방식은 정렬을 보장할 수
없으므로 쓰지 않는다.

## 6. 두 테마 · 프레임 · 가장자리

- 원칙: **자산 한 벌이 두 테마를 다 섬긴다.** 테마별 두 벌은 페이로드와 관리 비용을 두 배로
  만든다(WP6 §9-5 수용 검사 (5) 유지). 예외는 §6 마지막 줄.
- 방법: 모든 래스터는 `EditorialImage`의 **닫힌 프레임** 안에서만 렌더된다 — `rounded-lg` +
  `border border-line-500`(`ContentThumbnail`이 이미 쓰는 처리). 라이트 바탕 위의 어두운 사진은
  "테두리 있는 화보"로 읽히고, 다크 바탕 위에서는 테두리가 이미지와 바탕을 분리한다.
- 따라서 이미지는 **가장자리가 닫혀 있어야** 한다: 바탕색으로 페이드 아웃하는 비네트, 투명 PNG,
  바탕과 섞이는 "블리드" 연출 금지. 그런 이미지는 라이트 테마에서 검은 사각형이 된다.
- 프레임 바깥 4%는 `object-fit: cover` 크롭 허용 오차다. 중요한 디테일을 두지 않는다.
- **예외 — 전면 배경 텍스처**(매니페스트 VA-19·20): 프레임이 없으므로 다크/라이트 **두 벌**이 필요하다.
  그래서 P2이며, 라이트 벌이 성립하지 않으면 도입하지 않는다.

## 7. Fallback — 자산이 없을 때 무엇이 보이는가

자산은 옵트인 오버라이드이고, 기본은 생성 그래픽이다(WP6 ruling 106·114 유지). 계약 AB: 이미지가 없어도
레이아웃은 깨지지 않는다.

1. `EditorialImage`는 **항상 aspect-ratio 박스를 그린다**(CLS 0). 자산이 있으면 `next/image`, 없으면
   같은 박스 안에 `ContentThumbnail`의 topic×kind 선화를 `ground-800` 위에 중앙 배치한다. 박스의
   비율·프레임·테두리는 자산 유무와 무관하게 동일하다.
2. topic이 없는 슬롯(허브 히어로·about·404)은 kind 액센트만으로 그린 선화, 또는 **비주얼 슬롯 자체를
   생략**하고 단일 컬럼 타이포그래피 히어로로 접힌다. 접힌 상태가 기본 상태처럼 보여야 한다 —
   빈 회색 상자·"이미지 준비 중" 문구·깨진 이미지 아이콘은 금지.
3. 홈 히어로는 자산이 없을 때 기존 `HomeHeroVisual`(실제 카드 두 장 + 실제 13×13)을 그대로 쓴다.
   이것은 WP-3이 만든, 데이터에서 나오는 그림이며 "플레이스홀더"가 아니다.
4. 핸드 스토리 히어로가 없으면 카테고리 아트워크(VA-03), 그것도 없으면 `ContentThumbnail(blog, topic)`.
   체인: **story image → category art → ContentThumbnail**.
5. OG는 이미 `public/og.png`가 있다. 페이지별 OG가 없으면 이 한 장이 폴백이다.

## 8. 성능 규칙 (계약 AC·BY)

- 모든 페이지 래스터는 `next/image` + 명시 `width/height`(또는 `fill` + 부모 aspect box) +
  `sizes`. 원본 생성물(수 MB)을 그대로 서비스하지 않는다.
- 포맷: 페이지 비주얼 WebP(AVIF 선택). OG는 PNG(크롤러의 WebP 처리 미확인 — WP6 §7 유지).
- 예산(**budget**, 측정값 아님): 페이지 비주얼 ≤ 200 KB, 히어로 ≤ 300 KB, 카테고리/카드 ≤ 150 KB,
  텍스처 벌당 ≤ 120 KB, OG PNG ≤ 150 KB. 예산을 넘기면 압축을 올리거나 긴 변을 줄인다.
- `priority`는 **홈 히어로 한 장**만. 나머지는 lazy(기본값).
- alt: 장식 → `alt=""`. 의미 → 한국어 서술. 판정법은 WP6 §6 한 줄 — *"이 그림을 지웠을 때 사라지는
  사실이 있는가?"* 이 매니페스트의 AI 자산은 전부 분위기용이므로 **전부 `alt=""`**이고, 사실을 나르는
  것은 SVG 오버레이·도해(각자 `role="img"` + 이름)다.
- 파일명은 slug/topic 기반(계약 BV): `public/images/<role>/<slug>-<slot>.webp`. 해시 파일명 금지.
  자산이 들어오는 커밋에 디스크 대조 테스트를 같이 넣는다(WP6 §7 유지).
- 출처: `public/images/CREDITS.md`에 파일명·모델·프롬프트·생성일을 기록한다(라이선스 위생 스크립트가
  있는 저장소다).

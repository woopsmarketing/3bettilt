# FishTilt WP-3 — 홈 화면 리디자인

## 목표

홈이 밋밋한 원인은 취향이 아니라 구조였다. 9개 섹션 중 **시각 요소가 있는 것은 ③
(`HomeRangePreview`) 하나**였고 나머지 8개는 전부 카드 리스트였다. 히어로는 제목 + 문단 +
버튼 2개뿐이었다. 그래서 이번 WP는 (1) 히어로에 **이 사이트의 진짜 오브젝트**로 만든 시각 요소를
넣고, (2) 서로 같은 질문에 두 번 답하던 섹션을 합쳐 9 → 8로 줄이고, (3) 홈이 이 **사이트 자체에
대해** 답하는 FAQ 섹션을 만들고, (4) 레지스트리 배열 순서를 그대로 노출하던 글로서리 미리보기를
명시적 큐레이션으로 바꾸고, (5) WP-2가 남긴 `HomeLinkCard` 별칭을 삭제했다.

동시에 **홈이 근거 없는 주장을 하지 않는다**는 성질을 강화했다. `인기 무료 도구`라는 제목은
이 사이트에 분석 도구가 없어 검증 불가능한 주장이었고, 이번에 사라졌다.

## 범위

- **담당**: 오케스트레이션 브리프 A(히어로 시각 요소) · B(정보 구조 재배치) · C(FAQ 섹션 신규) ·
  D(글로서리 큐레이션, WP-1 우선순위 #4) · E(섹션 강화 + `HomeLinkCard` 삭제) · F(내부링크).
- **구속 조건**: FISHTILT_STATE ruling 100–112, 특히 105(날짜 없음 → 최신순 금지),
  107(화면에 없는 Q&A로 구조화 데이터 만들지 않기), 108(build/e2e 직렬화), 112(래스터에 텍스트
  금지). WP-2 산출물(토큰 16개 · 컨테이너 3종 · `LinkCard` · 타이포 스케일)만 재료로 썼다.
- **범위 밖**: `globals.css`(토큰 추가 없음 — 필요 없었다) · `routes.ts` · 허브 페이지 · 툴 페이지 ·
  `src/lib/seo/**` · 콘텐츠 MDX/레지스트리. 전부 손대지 않았다.
- **JSON-LD는 만들지 않았다.** `FaqSection`은 화면만 렌더한다. `FAQPage`는 WP-7 소관이며 같은
  배열에서 만들면 된다(§다음 WP에 넘길 사실 요약).

### 2. 히어로 시각 요소 — `HomeHeroVisual.tsx` (신규)

**무엇으로 그렸나: 이 사이트의 실제 오브젝트 두 개.**

1. **진짜 카드 2장** — `PokerCards hand="AKs"`. 카드는 `learn-core`의 `handClassFacts`가 주는
   그 클래스의 대표 콤보이고, `AKs / 에이스 킹 수티드 / 같은 무늬의 A와 K`라는 문구는
   `features/range/copy.ts`가 만든다. 히어로가 직접 타이핑한 문장이 아니다.
2. **진짜 13×13 표의 축소판** — `HAND_CLASSES` 169개를 그대로, `RangeMatrix`와 **같은 row-major
   구성**으로 그린다. 채움은 `resolveRange({BTN, RFI, 100BB, 6인})`가 답한 실제 레인지다.

그리고 한 문장이 둘을 잇는다 — `받은 두 장은 표에서 한 칸입니다. 표에는 169칸이 있습니다.`
(169는 `HAND_CLASSES.length`, 손으로 적은 숫자가 아니다.) 이것이 이 사이트가 가르치는 첫 번째
생각이고, 히어로가 문장 대신 그림으로 말한다.

**왜 `RangeMatrix`를 그대로 쓰지 않았나.** 44px 셀 × 13 = 608px 스크롤러 + `<button>` 169개 +
클라이언트 컴포넌트다. 히어로에 놓으면 (a) 첫 링크 앞에 **탭 스톱 169개**가 생기고, (b) 375px에서
CTA를 첫 화면 밖으로 밀어낸다. 그래서 **비인터랙티브 썸네일**이다 — `<span>` 169개, 상태 없음,
클라이언트 JS 0바이트, `role="img"` 하나. 방향(orientation)은 `RangeMatrix`와 동일하게
`HAND_CLASSES` 배열 순서 자체이며, `handClassAt`에 대해 **구체적 셀 3개를 테스트로 고정**했다
(`RangeMatrix.test.tsx`와 같은 방식).

**제약 준수**

| 제약 | 어떻게 지켰나 |
|---|---|
| 텍스트를 이미지로 굽지 않기(ruling 112) | 라벨·범례·조건은 전부 DOM 텍스트. 표는 `role="img"` + `aria-label`(문자열)이고 픽셀에 글자가 없다. 이미지 파일 0개, `public/` 변경 0건 |
| 375px에서 CTA가 첫 화면 밖으로 밀리지 않기 | DOM 순서가 h1 → 설명 → CTA → 시각 요소다. 모바일은 1열이므로 시각 요소가 **항상 CTA 아래**. `lg:` 이상에서만 2열이 된다. **브라우저에서 `toBeInViewport()`로 실측**하는 e2e를 추가했다 |
| 애니메이션 | 넣지 않았다. `transition`도 없다 |
| 라이트/다크 | 색은 전부 역할 토큰. 두 테마 스크린샷으로 육안 확인 |

**표시된 칸에 링(ring)을 두른 이유 — 계산해서 결정했다.** `RangeMatrix`는 선택 셀을 브랜드
채움만으로 구분할 수 있다 — 그 셀에는 `aria-pressed`, 굵은 글씨, 그리고 셀 안에 인쇄된 키가 함께
있기 때문이다. 썸네일에는 글자가 없고, `brand-600` 대 `act-raise-500`은 **명도 차가 아니라 색상
차**다:

| 페어 | 다크 | 라이트 |
|---|---|---|
| `brand-600` vs `act-raise-500` (채움끼리) | **1.38:1** | **1.54:1** |
| `ink-on-brand` vs `brand-600` (링 대 채움) | **5.09:1** | **8.08:1** |

즉 적록색약 독자는 "위 두 장이 있는 칸"을 못 찾는다. `ink-on-brand`는 역할이 정확히 "브랜드 채움
위의 잉크"이고, 팔레트에서 이 채움에 대해 **두 테마 모두 3:1 UI 하한을 넘는 유일한 토큰**이며,
`theme-tokens.test.ts`가 이미 이 페어를 감사하고 있다. `outline`/`ring`이 아니라 `border-2`인
이유는 `box-sizing: border-box` 덕에 셀 안쪽에 그려져 **그리드 기하가 움직이지 않고 2px 간격으로
번지지 않기** 때문이다. 빌드 산출 CSS에서
`border-ink-on-brand{border-color:var(--color-ink-on-brand)}`가 `var()` 참조를 유지하는 것을
확인했다(= 테마 오버라이드가 먹는다).

**조건은 절대 빠지지 않는다.** `BTN · 학습용 기본 레인지`와
`6인 · 100BB · 아무도 참여하지 않았을 때 (First In)`이 표 아래 텍스트로 항상 있고, 3색 범례가
말로 적혀 있다(색만으로 전달하지 않음, WCAG 1.4.1). 만약 쿼리가 해석되지 않으면 채움 없는
NEUTRAL 상태로 떨어지고 범례·조건 줄도 사라진다 — 빌려온 레인지를 그리지 않는다.

### 3. FAQ 섹션 — `FaqSection.tsx` (신규)

**WP-1 §7-2와의 관계를 먼저 밝힌다.** WP-1은 "허브 5개 · `/practice` · 홈 → FAQ 만들지 않음"으로
결정했다. 그 근거는 *목록 페이지에 얇은 포커 Q&A를 얹는 것*이 부풀리기라는 것이었다. 이번 홈 FAQ는
**포커 질문을 하나도 답하지 않는다** — 무료인지, 포커를 몰라도 되는지, 어디서 시작하는지, 숫자가
어디서 나오는지, 제휴하는지, 어떤 상황까지 다루는지. 즉 WP-1이 막으려던 카니발라이제이션의 대상이
아니고, 오케스트레이터 브리프가 명시적으로 지시한 범위다. WP-1 §7-2의 판단은 포커 Q&A에 대해서는
그대로 유효하다.

**홈 FAQ 6문항 (전부 이 저장소가 근거를 가진 것만)**

| # | 질문 | 답의 근거 | 따라가는 링크 |
|---|---|---|---|
| 1 | FishTilt는 무료인가요? | 앱에 auth·payment·ads 코드 0건 | 없음 |
| 2 | 포커를 전혀 몰라도 되나요? | 커리큘럼이 규칙부터 시작 + §48 첫 등장 쉬운 한국어 정책(`<Term>`) | `/glossary` |
| 3 | 어디서부터 시작하면 되나요? | 읽을 수 있는 강의 수·퀴즈 수는 그래프에서 계산 | 첫 강의 |
| 4 | 화면에 나오는 숫자는 어디서 나온 건가요? | `/about`의 "숫자는 어디서 나오나요" 절 | `/about` |
| 5 | 어떤 포커 사이트와 제휴하나요? | `/about`의 "제휴하지 않습니다" 절 | `/about` |
| 6 | 핸드레인지 표는 어떤 상황을 기준으로 하나요? | `describeRangeConditions()`가 만든 문자열 + `RANGE_LABEL` | `/tools/range` |

**컴포넌트 설계 (WP-7이 그대로 쓴다)**

- 아이템 타입은 **`src/lib/seo/faq.ts`의 `FaqItem`을 import**해서 확장한다. 새로 선언하지 않은
  이유는 WP-7이 같은 배열로 `FAQPage`를 만들기 때문 — 두 벌이 되면 드리프트한다.
  ```ts
  export interface FaqEntry extends FaqItem {           // FaqItem = { question, answer }
    readonly link?: { readonly href: string | null; readonly label: string };
  }
  ```
- **`answer`는 순수 텍스트**다. `FAQPage`의 답변은 문자열이고, 답변 안에 마크업을 넣는 순간
  화면과 구조화 데이터가 달라진다. 링크가 필요하면 `link`로 **답변 바깥에** 붙는다
  (ruling 107). 테스트가 "답변 노드 안에 `<a>`가 없다"를 고정한다.
- `href: string | null` — 이 사이트의 모든 목적지와 같은 규약. `null`이면 링크만 사라지고 답변은
  남는다.
- **아코디언이 아니다.** 6개 짧은 답변에 숨길 것이 없고, 이건 독자가 "이 사이트를 믿을지"
  판단하는 문장이라 한 번 더 눌러야 보이면 안 된다. 크롤러 관점도 같다.
  `<details>`·`aria-expanded`·`[hidden]`이 0건임을 유닛/e2e 양쪽에서 고정했다.
- 자기 자신이 `<section aria-label={title}>`을 렌더한다 → **WP-7이 툴 4개 페이지에 그대로 얹을 수
  있다**(WP-1 §7-2가 "훅 신규 필요"라고 적은 그 자리).
- 후속 링크는 `inline-flex min-h-11` — 문장 속 인라인 링크가 아니라 **독립 컨트롤**이므로 44px
  터치 타깃 규칙(WP-O1)의 대상이다. 첫 e2e 실행이 정확히 이걸 잡아서 고쳤다.

### 4. 글로서리 미리보기 큐레이션

```ts
const HOME_GLOSSARY_PICKS = [
  'term-pot', 'term-fold', 'term-flop', 'term-blind', 'term-position', 'term-range',
];
```

WP-1 §4의 권고 그대로다. 선정 기준은 **"한 판이 진행되는 것을 따라가는 데 필요한 말"**이고
레지스트리 순서와 독립적이다. published가 아닌 id는 렌더하지 않고 조용히 건너뛰되,
`page.test.tsx`가 **6장이 렌더되는지**를 고정하므로 pick이 해석되지 않으면 카드가 소리 없이
사라지는 대신 테스트가 깨진다. 추가로 "노출된 6개가 `publishedOfKind('glossary')`의 앞 6개와
같지 않다"를 assert해서 누가 `slice()`로 되돌리면 즉시 실패한다.

### 5. 나머지 섹션 강화

- **섹션 2**를 `ground-800` 우물 + `line-500` 테두리 위에 얹고 `lg:grid-cols-4`로 한 줄에 4칸.
  카드는 `panel-700`이라 우물 위에서 떠 보인다(WP-2가 문서화한 표면 사다리 그대로). 페이지에서
  유일하게 "고르는 곳"으로 읽힌다.

  옆에 요약 패널이 들어갈 공간이 생긴다. 섹션 간격은 `mt-section`, 페이지 패딩은

- 레슨·툴·퀴즈 그리드를 `lg:grid-cols-3`으로 — 2열 카드가 계속 반복되던 리듬을 끊는다.
- **`HomeLinkCard.tsx` 삭제 완료.** 호출부 9곳 전부 `LinkCard` 직접 import.
- 카드 썸네일 자리(`visual` 프롭)는 **비워 뒀다** — WP-5 소관.

## 남은 이슈

1. **`LinkCard.test.tsx`는 내 파일 경계 밖이었지만 수정이 불가피했다.** 그 파일이
   `HomeLinkCard.js`를 import하고 있어서, 브리프가 지시한 삭제를 하면 파일이 컴파일되지 않는다.
   assertion을 **삭제하지 않고** 더 강한 것(파일시스템 기준 "카드 컴포넌트는 하나")으로 교체했다.
   `LinkCard.tsx`도 주석 한 문단만 갱신했다(삭제된 파일을 가리키고 있었다). 마스터 확인 요청.
2. **히어로 썸네일의 표시 셀은 `border-2 border-ink-on-brand`를 쓴다.** `globals.css`는
   `line-500`을 "유일한 테두리·구분선"으로 규정하는데, 이건 구분선이 아니라 **색약 대응 마커**이고
   `line-500`은 이 채움 위에서 1.03:1로 쓸 수 없다. 판단 근거는 §구현 내용 2의 표에 남겼다.
   토큰 규약 문구를 "구분선은 line-500, 채움 위 마커는 ink-on-*"로 다듬을지는 토큰 소유자 판단.
3. **히어로가 1280px에서 세로로 길다**(약 950px). 오른쪽 패널 높이 때문에 왼쪽 텍스트 위에 여백이
   생긴다. 의도된 히어로처럼 읽히지만, WP-8이 더 조이고 싶다면 카드를 `size="sm"`으로,
   썸네일을 `max-w-[18rem]`으로 줄이면 약 80px 준다.
4. **`--color-brand-950` 사용처 여전히 0건** (WP-2 §남은 이슈 5). 이번에도 쓰지 않았다.
5. **`text-500`은 여전히 본문 미달**이며 홈에서 쓰지 않았다 (WP-2 §남은 이슈 6).
6. **`prefers-contrast: more` 미대응** (WP-2 §남은 이슈 8) — 그대로.
7. **글로서리 고아 3건은 이번 WP가 해결하지 않았다.** §다음 WP에 넘길 사실 요약 참조. 링크를
   유지하려고 큐레이션을 왜곡하지 않았다.

### WP-7 (SEO / JSON-LD)

- **홈 `FAQPage`는 `src/app/page.tsx`의 `faqItems` 배열에서 만들어라.** 다른 어떤 소스도 안 된다.

  넘기면 되고, `link`는 답변 텍스트가 아니므로 **JSON-LD에 넣지 마라**.
- 홈은 화면에 6문항을 렌더하므로 `MIN_FAQ_ITEMS`(2)를 넉넉히 넘고, 기존 e2e
  `every FAQPage question is a question the page actually shows`를 그대로 만족한다.
- **`FaqSection`은 툴 페이지에 그대로 얹을 수 있다.** 자기 `<section aria-label>`을 렌더하고

  쓴다"고 적은 4개 툴(`pot-odds`, `outs`, `equity`, `range`)의 훅이 이것이다.
- 홈이 새로 링크하는 곳: `/hands`, `/about`. sitemap은 변화 없다(새 라우트 0개).

### WP-5 (썸네일 / 히어로 이미지)

- **`LinkCard`의 `visual` 프롭은 홈에서도 비어 있다.** 홈의 카드 9개 그룹 전부 `LinkCard`이므로
  프롭을 채우면 홈에도 자동으로 나타난다. 홈 전용 카드 마크업은 이제 존재하지 않는다.
- **히어로에는 이미 시각 요소가 있다.** `HomeHeroVisual`을 이미지로 교체하지 마라 — ruling 112가
  요구하는 "라이브 텍스트" 형태를 이미 만족하고, 클라이언트 JS가 0이다.
- `HomeHeroVisual`의 13×13 썸네일 렌더 방식(`HAND_CLASSES` row-major + 3색 토큰 + `aspect-square`
  그리드)은 **콘텐츠 썸네일에 그대로 재사용할 수 있는 형태**다. 다만 조건 문구 없이는 레인지를
  그리지 마라.

### WP-8 (최종 QA)

- 홈 회귀는 `src/app/page.test.tsx`(18 tests)와 `tests/e2e/home.spec.ts`(25 tests)가 잡는다.
  섹션 이름을 바꾸면 두 파일의 `SECTION_NAMES` / `SECTIONS` 배열을 같이 고쳐야 한다.
- `responsive-a11y.spec.ts`는 `/`에서 `role="group"`으로 13×13과 자리 버튼을 찾는다. 히어로
  썸네일은 `role="img"`라 여기에 걸리지 않는다 — **히어로에 `role="group"`을 붙이지 마라.**
- `theme-and-header.spec.ts`의 hover 대비 측정은 `/`의 `a.bg-brand-600` **첫 번째**를 쓴다. 이는
  히어로 primary CTA다 — 히어로에서 채움 버튼을 없애면 그 테스트가 다른 것을 잡는다.
- 새 시각 요소를 추가하면 스크린샷이 아니라 **계산된 스타일로 대비를 측정**할 것(WP-2 규약).
  이번 히어로의 채움끼리 대비(1.38 / 1.54)는 계산해서 링으로 보완한 값이다.

### 모두에게

- **홈은 이제 8섹션이고, 각 섹션은 서로 다른 질문에 답한다.** 섹션을 추가하려면 "기존 8개 중 어느
  것도 답하지 않는 질문"을 먼저 말할 수 있어야 한다. 모듈 주석에 그 목록이 있다.
- **홈 컨테이너는 `max-w-shell`**(72rem)이다. 헤더와 정렬된다.
- **`인기`/`최신`/`신규`는 홈 헤딩에 쓸 수 없다.** 테스트가 막는다. analytics도 날짜 필드도 없다.
- **카드 컴포넌트는 `LinkCard` 하나뿐**이고, 두 번째가 생기면 `LinkCard.test.tsx`가 파일시스템에서
  잡아낸다.

## WP-3b 후속

마스터 승인 후 지적된 **두 가지만** 고쳤다. 섹션 구성 8개, FAQ 6문항, 글로서리 큐레이션,
`border-ink-on-brand` 링 판단은 승인된 그대로 손대지 않았다.

### 1. 데스크톱 히어로 상단의 빈 공간 (남은 이슈 3의 실제 원인)

**증상**: 1280×900에서 헤더는 77px에서 끝나는데 h1이 370px에서 시작 — **그 사이 293px이 공백**.
"여백이 넉넉하다"가 아니라 "위가 비었다"로 읽힌다.

**원인은 여백 값이 아니라 산술이다.** 히어로 그리드가 `lg:items-center`였다. 오른쪽 그림은
628px, 왼쪽 텍스트 열은 약 430px이므로, 짧은 열을 긴 행 높이 안에서 세로 중앙에 두면 헤드라인이
차이의 절반(약 100px)만큼 아래로 밀린다. 여기에 그림 자체가 만든 행 높이가 더해져 293px이 됐다.
**패딩을 줄이는 건 증상 치료**라서 택하지 않았다 — `py-20`은 이 사이트의 모든 페이지가 쓰는 값이고,
히어로만 다르게 하면 헤더 아래 리듬이 페이지마다 달라진다.

**수정**: `src/app/page.tsx` 히어로 그리드 한 줄, `lg:items-center` → **`lg:items-start`**.
새 토큰은 만들지 않았고 `--spacing-section`도 건드리지 않았다. 필요한 토큰이 모자라지 않았다.

**실측 (프로덕션 빌드, 포트 3221, 다크/라이트 동일)**

| 값 | before | after |
|---|---|---|
| 헤더 하단 → h1 상단 | **293px** | **80px** |
| h1 상단 / 그림 상단 | 370 / 157 | **157 / 157** (동일선) |
| CTA 그룹 하단 | 화면 안 | **311px** |
| 비제휴 문구(`소개` 링크 포함) 하단 | 화면 안 | **355px** |

900px 뷰포트 기준으로 CTA 2개와 비제휴 문구가 첫 화면 위쪽 **40% 안**에 전부 들어온다.
80px은 페이지 자신의 `py-20`(5rem)이다 — 즉 히어로가 다른 페이지와 같은 자리에서 시작한다.

### 2. 375px에서 CTA 두 개의 폭 불일치

**증상**: `처음부터 배우기` 141px, `13×13 핸드레인지 보기` 192px. 줄바꿈으로 세로로 쌓이는데
폭이 51px 어긋나 **위계가 아니라 정렬 실수로 읽힌다.**

**원인**: CTA 그룹이 `flex flex-wrap`이었다. 행을 감싸면 각 버튼은 자기 라벨 길이만큼만 넓어진다.

**수정**: `flex flex-wrap gap-3` → **`flex flex-col gap-3 sm:flex-row sm:flex-wrap`**.
열로 쌓이면 flex 기본 `align-items: stretch`가 두 버튼을 같은 폭으로 늘린다.
`sm` 이상에서는 이전과 완전히 동일한 나란한 배치 — 데스크톱은 바꾸지 않았다.
`HomeCallToAction.tsx`는 수정하지 않았다(버튼 자체에 폭을 박으면 데스크톱까지 깨진다).

**실측**: 375×812에서 CTA 폭 `[141, 192]` → **`[327, 327]`** (다크/라이트 동일),
두 버튼의 세로 순서(primary가 위)도 유지.

### 고정한 테스트 (e2e 3개 추가, 픽셀 하드코딩 없음)

`tests/e2e/home.spec.ts`:

1. `the two hero CTAs are the same width when they stack on a phone` — 375×812에서
   `widths[0] === widths[1]`(값이 아니라 **동일성**을 본다) + primary가 위에 있는지.
2. `the headline starts level with the hero picture, not floated to its middle` — 1280×900에서
   `h1Top - cardTop < cardHeight / 4`. **관계식이라 그림 높이가 바뀌어도 살아남는다.**
3. `the whole hero — CTAs and the honesty line — is on the first desktop screen` — 1280×900에서
   h1·CTA 2개·비제휴 `소개` 링크 전부 `toBeInViewport()`. 지시대로 "뷰포트 안에 보이는가"만 본다.

기존 375px `toBeInViewport()` 검사도 그대로 남아 있어 모바일 첫 화면도 계속 고정된다.

### 검증 결과

| 게이트 | 명령 | WP-3 → WP-3b |
|---|---|---|
| 유닛 | `pnpm vitest run --project fishtilt --project learn-core` | **1600 → 1600 / 0 fail** (133 files) |
| 타입 | `pnpm typecheck` | 0 errors → **0 errors** |
| 린트 | `pnpm lint` | clean → **clean** |
| 빌드 | `pnpm build:fishtilt` | **131페이지 전부 정적 유지** (정적 ○ 24 + SSG ● 113 = 프리렌더 137, 동적 0) |
| E2E | `pnpm e2e:fishtilt` | **235 → 238 passed / 0 fail** (홈 스펙 25 → 28) |
| 포맷 | `prettier --list-different` | **0** |

유닛 수가 그대로인 것은 의도된 것이다 — 이번 변경은 레이아웃이고, jsdom에는 레이아웃이 없다.
폭과 위치는 실제 렌더러가 있는 e2e에서만 의미가 있으므로 거기서만 고정했다.

**육안 재확인**: 다크/라이트 × 1280×900 · 375×812 4장을 다시 촬영해 실제 픽셀로 확인
(scratchpad 저장, 저장소에 남기지 않음). 다크·라이트 모두 헤드라인이 그림 상단과 같은 선에서
시작하고, 두 버튼이 같은 폭으로 쌓인다.

### 이 후속으로 갱신되는 항목

- **남은 이슈 3**(히어로가 세로로 길다)은 원인이 "카드 높이"가 아니라 **정렬**이었고, 이번에
  해소됐다. 그림이 아직 텍스트보다 길어 히어로 전체 높이는 그대로지만, 그건 히어로 이미지가
  원래 하는 일이고 첫 화면 안쪽에는 영향이 없다. 카드를 `size="sm"`으로 줄이라는 제안은
  **더 이상 필요하지 않다** — WP-8은 이 항목을 닫아도 된다.
- **WP-8에게**: 히어로 CTA 그룹은 `sm` 미만에서 세로 스택이고 두 버튼 폭이 같아야 한다.
  `HomeCallToAction`에 폭 클래스를 추가하면 데스크톱 나란한 배치가 깨진다 — 폭은 그룹이 정한다.

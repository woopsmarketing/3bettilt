### `drizzle-kit generate` was overridden, deliberately

For this diff the generator emits the SQLite 12-step table-recreate:
`CREATE TABLE __new_hands … INSERT … SELECT "source","schema_version" FROM hands … DROP TABLE
hands …`. That output is (a) broken — it selects the columns being added — and (b)
catastrophic: its `PRAGMA foreign_keys=OFF` is a no-op inside the migrator's transaction, so
`DROP TABLE hands` would cascade every `hand_events` / `hand_players` row away (ADR-0046).
The generated `.sql` was replaced with hand-authored `ALTER TABLE … ADD COLUMN`; the
generated snapshot and journal entry were kept.

### `CHECK` on `ALTER TABLE ADD COLUMN` — verified, works

The brief asked whether SQLite accepts a column-level CHECK on ADD COLUMN. **It does** (and a
`NOT NULL` with a non-NULL DEFAULT does too). Verified by reading `sqlite_master` after
migration — the stored `CREATE TABLE hands` carries both new constraints verbatim:

```
`source` text DEFAULT 'MANUAL_PRACTICE' NOT NULL CONSTRAINT "hands_source"
  CHECK("hands"."source" in ('MANUAL_PRACTICE', 'MANUAL_REVIEW')),
`schema_version` integer DEFAULT 1 NOT NULL CONSTRAINT "hands_schema_version_positive"
  CHECK(typeof("hands"."schema_version") = 'integer' and "hands"."schema_version" >= 1)
```

No fallback to repository-only validation was needed. (Decoder validation in `rows.ts` was
added anyway, matching the package's existing belt-and-braces convention for enums.)

## 2. Migration 0004 contents

**Columns (additive, no table rewrite):**

- `hands.source TEXT NOT NULL DEFAULT 'MANUAL_PRACTICE'`, CHECK in
  `('MANUAL_PRACTICE','MANUAL_REVIEW')`.
- `hands.schema_version INTEGER NOT NULL DEFAULT 1`, CHECK `typeof(...) = 'integer' and >= 1`.

**Triggers (six, `RAISE(ABORT, …)`, same style as `0001`):**

| Trigger | Fires | Message contains |
|---|---|---|
| `hand_events_no_update` | `BEFORE UPDATE`, unconditional | `hand_events is insert-only` |
| `hand_events_no_delete` | `BEFORE DELETE`, unconditional | `hand_events is insert-only` |
| `hand_players_no_update` | `BEFORE UPDATE`, unconditional | `hand_players is insert-only` |
| `hand_players_no_delete` | `BEFORE DELETE`, unconditional | `hand_players is insert-only` |
| `hands_no_update_once_finished` | `BEFORE UPDATE … WHEN OLD.finished_at IS NOT NULL` | `hands is immutable once finished` |
| `hands_no_delete` | `BEFORE DELETE`, unconditional | `hands is immutable` |

Consequences: `markHandFinished` still works on an unfinished row and aborts on a finished
one (that abort arrives as `STORAGE_FAILURE`, not `CONSTRAINT_VIOLATION` — a trigger abort is
not a constraint marker, and `attempt` maps it accordingly). The `ON DELETE CASCADE` from
`hands` to `hand_events` / `hand_players` is unreachable, because `hands` cannot be deleted.

The full trigger list (12, including 0001's six) is pinned exhaustively in
`tests/insert-only.test.ts`.

## 3. New repository surface (exact signatures)

```ts
// packages/db/src/repositories/hands.ts

export interface InsertCompletedHandInput {
  readonly sessionId: SessionId;
  readonly hand: Hand;              // must be COMPLETE
  readonly startedAt: Timestamp;
  readonly finishedAt: Timestamp;
  readonly source?: HandSource;     // default 'MANUAL_PRACTICE'
}

export type CompletedHandOutcome = 'PERSISTED' | 'ALREADY_PERSISTED';

export interface InsertCompletedHandResult {
  readonly handId: HandId;
  readonly outcome: CompletedHandOutcome;
}

export function insertCompletedHand(
  db: GtoDatabase,
  input: InsertCompletedHandInput,
): DbResult<InsertCompletedHandResult>;

export function listCompletedHandIdsForPlayer(
  db: GtoDatabase,
  playerId: PlayerId,
): DbResult<readonly HandId[]>;

export function listCompletedHandsForSession(
  db: GtoDatabase,
  sessionId: SessionId,
): DbResult<readonly HandRecord[]>;

export function listPlayerIdsWithCompletedHandsInSession(
  db: GtoDatabase,
  sessionId: SessionId,
): DbResult<readonly PlayerId[]>;

export function loadCompletedHands(
  db: GtoDatabase,
  handIds: readonly HandId[],
): DbResult<readonly Hand[]>;
```

```ts
// packages/db/src/schema.ts
export const HAND_SOURCES: readonly ['MANUAL_PRACTICE', 'MANUAL_REVIEW'];
export type HandSource = 'MANUAL_PRACTICE' | 'MANUAL_REVIEW';
export const CURRENT_HAND_SCHEMA_VERSION = 1;

// packages/db/src/rows.ts — HandRecord gained:
readonly source: HandSource;
readonly schemaVersion: number;
```

All are re-exported through the package barrel (`src/index.ts` already `export *`s both
modules).

### Semantics

- **Completion precondition.** `hand.state.phase === 'COMPLETE'` **and** the log's last event
  is `HAND_FINISHED`. Both, because the state is caller-supplied while the log is
  authoritative (ADR-0039) — a `COMPLETE` state over a truncated log is refused too. Failure
  is `INVALID_INPUT` and nothing is written.
- **One transaction**: header (with `finished_at`, `source`, `schema_version`) +
  `hand_players` + all events. `finished_at` is never a second UPDATE — the ADR-0060 trigger
  would refuse it anyway.
- **Exactly-once.** `hands.id` (the engine's stable `handId`) is the primary key. The
  function probes for that row before writing:
  - existing row and it **is** this hand → `ok({ handId, outcome: 'ALREADY_PERSISTED' })`,
    **nothing written at all** (not even `finished_at`);
  - existing row that **disagrees** → `err(CONFLICT)` with `context.field` naming what
    disagreed.
- **Integrity probe (documented choice).** Three cheap comparisons: `session_id`,
  `hand_number`, and `count(hand_events)` vs `hand.events.length`. Deliberately *not* a
  full log comparison: every duplicate callback would then pay an O(log) decode. It is a
  tripwire for a genuine id collision (a colliding id factory, a reused fixture id, a caller
  mixing up two hands), not a checksum of history. A different hand that happened to match
  all three would be reported as `ALREADY_PERSISTED`; that is accepted, because `handId` is
  engine-generated and stable.
- **Ordering determinism.** `listCompletedHandIdsForPlayer` orders by `started_at`, then `id`
  — required because C1 identifies a recomputation by a hash over its input hand ids and two
  hands can share a millisecond. `listCompletedHandsForSession` orders by `hand_number`
  (unique within a session). `listPlayerIdsWithCompletedHandsInSession` orders by player id.
- **`loadCompletedHands`** returns hands in the order requested and fails the whole batch
  (`NOT_FOUND`) on an unknown id or an unfinished hand — never a silently shorter list.
- **`hand_players.player_id IS NULL`** (unidentified opponent) contributes no player id to
  the discovery query.
- ADR-0040 preserved: no clock read, no id generated anywhere in the new code.

## 6. Risks / notes for downstream WPs

1. **`HandRecord` gained two required fields.** Any consumer constructing a `HandRecord`
   literal (none exist outside `packages/db` today) must supply `source` and `schemaVersion`.
   Read-only consumers are unaffected.
2. **A trigger abort is a `STORAGE_FAILURE`, not a `CONSTRAINT_VIOLATION`** — SQLite reports
   `RAISE(ABORT, …)` with the raw message and no constraint marker, so `attempt` cannot
   classify it. UI code that wants to distinguish "history rewrite refused" must match the
   message, or (better) never take that path.
3. **`markHandFinished` on an already-finished hand now fails.** No caller does this today
   (nothing calls it at all), and `insertCompletedHand` does not use it. If a future
   live-persistence phase inserts headers early, it must call `markHandFinished` exactly
   once.
4. **`withoutInsertOnlyGuards` now drops the hand-history triggers too** (it reads them from
   `sqlite_master` and restores them verbatim, so it stays in step automatically). Tests that
   deliberately corrupt `hand_events` must wrap the mutation in it.
5. **The integrity probe is a tripwire, not a checksum** — see §3. If C1 ever needs a strict
   "is the stored hand byte-identical to this one" check, that is a separate function, not a
   loosening of this one.
6. **Trigger maintenance is manual.** `drizzle-kit` will never emit a trigger; the exhaustive
   list in `tests/insert-only.test.ts` is the only thing that notices a missing one. A new
   insert-only table in C1 (`analysis_runs`, `player_model_snapshots`, `player_spot_stats`)
   needs its own hand-authored migration **and** an update to that list.
7. **Nothing calls `insertCompletedHand` yet.** The `apps/web` wiring (ADR-0059c/e — an
   unawaited server action off the COMPLETE transition, with a visible failure banner) is a
   different WP and outside this file boundary.
